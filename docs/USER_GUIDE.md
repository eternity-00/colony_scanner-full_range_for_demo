## 1. 실행과 종료

바탕화면의 **Colony Scanner React Demo**를 더블클릭하거나 다음을 실행한다.

```sh
cd /home/miru/cc-lcd/react-demo
./open-demo.sh
```

한 번의 실행으로 두 창이 열린다.

1. **Colony Scanner LCD** — 운영 화면, `http://127.0.0.1:8787`
2. **Colony Virtual Device Console** — 외부 가상장비, `http://127.0.0.1:8792`

외부 장비 엔진은 별도 프로세스로 `http://127.0.0.1:8790`에서 동작한다. 두 창을 닫은 뒤 서버까지 종료하려면 `./stop-demo.sh`를 실행한다.

LCD만 새로 열려면 `./open-demo.sh`, 가상장비 창만 다시 열려면 `./open-virtual-device.sh`를 사용한다.

## 2. 권한 전환

초기 권한은 **분석자**다. 헤더 오른쪽의 사용자 칩을 누르고 4자리 PIN을 입력하면 관리자로 전환된다. 데모 기본 PIN은 `0000`이다.

- PIN을 5회 틀리면 60초간 입력할 수 없다.
- 관리자 상태는 황색 사용자 칩으로 표시된다.
- 4분 30초 동안 조작하지 않으면 30초 카운트다운이 나타난다.
- 5분 무조작 시 자동으로 분석자로 복귀한다.
- 즉시 복귀하려면 사용자 칩 또는 설정의 권한 설정에서 **분석자로 전환**을 누른다.

분석자도 등록·촬영·반출·검사 루틴·장비 관리 기능을 사용할 수 있다. **권한 설정 메뉴만 관리자에게 표시된다.**

## 3. 기본 운영 절차

### 플레이트 등록

1. 하단 **등록**을 누른다.
2. 연결 정상이며 빈 슬롯이 있는 스캐너를 선택한다.
3. 8×3 트레이에서 빈 슬롯을 선택한다.
4. 투입 시각을 입력하거나 **지금**을 누른다.
5. 첫 촬영과 총 회차를 확인하고 **등록하고 수납**을 누른다.
6. 추가 등록은 **계속 등록**, 끝내려면 **완료**를 누른다.

### 촬영

1. 현황에서 스캐너 **상세**를 누른다.
2. 촬영할 플레이트 좌표를 선택한다.
3. **지금 촬영**을 누른다.
4. 진행 화면에서 6단계, 진행률, WELL 1/6 프리뷰와 촬영 큐를 확인한다.
5. 필요하면 일시정지·재개 또는 확인 후 비상정지를 실행한다.

자동 촬영은 설정의 검사 루틴에서 활성화한다. 도어 열림, 장비 오류, 외부 엔진 단절 상태에서는 촬영할 수 없다.

### 영상 보기

상세의 촬영 이력에서 보유 상태 회차의 **보기**를 누른다. 화면은 6-well 전체 배열을 보여주지 않고 원형 프레임의 **한 웰, WELL 1/6**만 표시한다. 데모에서는 모든 회차에 같은 공개 이미지를 사용한다.

플레이트별 최근 5회차만 볼 수 있다. 더 오래된 회차는 보존기간 경과로 표시되고 메타데이터는 남는다. 반출하면 보유 영상이 제거된다.

### 재전송과 반출

- 미전송이 있으면 상세에서 **재전송**을 누른다. 장비와 PC 링크가 모두 연결돼야 한다.
- **플레이트 반출**은 확인 후 슬롯을 비우고 영상 참조를 삭제한다. 이력은 유지된다.

## 4. 화면 안내

### 현황

4개 스캐너의 수납, 오늘 촬영, 상태, 트레이와 경고를 본다. 헤더 링크는 연결 대수와 오류 수를 함께 표시한다.

### 이력

플레이트 ID 또는 `S2 4단 2열` 형식으로 검색한다. 기간·스캐너·전송 상태를 필터링할 수 있으며 **CSV 내보내기**로 현재 검색 결과를 저장한다.

### 장비

유선 링크, 카메라, 구동 4축, 히팅, 조명, 전원을 확인한다. 활성 오류 안내에 따라 도어·간섭을 확인하고 원점 복귀 또는 확인 후 오류 해제를 실행한다.

캘리브레이션 종류는 카메라 초점·배율, 구동 4축 원점, 히팅 온도, 조명 광량이다. 전체 재초기화는 확인 후 실행된다.

### 설정

- **검사 루틴:** 촬영 주기, 총 배양 기간, 시작 지연과 자동 촬영. 저장 시 전체 일정 재산정 확인이 표시된다.
- **온도·CO₂:** 외부 엔진의 4개 장비 목표값을 함께 변경한다.
- **유선 통신:** 스캐너별 링크 상태를 본다.
- **로그·백업:** 로그 JSON과 현재 상태 JSON을 내려받는다.
- **장비 정보:** 앱·엔진·스캐너 정보와 헤더에 표시할 운영자명을 관리한다.
- **권한 설정:** 관리자 세션에서만 보이며 자동 해제와 잠금 정책을 확인한다.

## 5. 외부 가상장비 사용

Virtual Device Console은 LCD와 분리된 프로그램 창이다. 각 스캐너에서 다음 입력을 조작한다.

- 장비 통신 연결
- PC 전송 링크
- 도어 센서 열림
- 카메라 실패
- Z축 오류 또는 히터 오류 주입
- 오류 해제

아래 OUTPUT은 Z축, 조명, 히터, 작업 진행률을 보여준다. 최근 I/O 패킷에서 명령 TX, ACK, 단계·완료 이벤트 RX를 확인한다.

엔진 단절을 시험하려면 `8790` 엔진 프로세스를 종료한다. LCD는 잠시 후 링크 0/4와 ENGINE_OFFLINE 상태로 바뀐다. `./open-demo.sh`를 다시 실행하면 엔진이 시작되고 연결이 복구된다.

## 6. 오류 대응

| 표시 | 조치 |
|---|---|
| ENGINE_OFFLINE / 링크 0/4 | `./open-demo.sh`로 외부 엔진 시작 |
| DOOR_OPEN | 콘솔에서 도어를 닫고 LCD 장비 화면에서 오류 해제 |
| Z_LIMIT | 간섭을 확인하고 원점 복귀 후 오류 해제 |
| HEATER | 히팅 상태 확인 후 오류 해제 |
| CAMERA_TIMEOUT | 콘솔의 카메라 실패를 끄고 오류 해제 |
| PC_OFFLINE | 장비 통신과 PC 전송 링크를 모두 켠 뒤 재전송 |
| PIN 잠금 | 표시된 60초가 지난 뒤 다시 입력 |

## 7. 개발·검사

```sh
npm install
npm run check
```

검사는 권한 전환·잠금·자동 해제, 플레이트 흐름, 외부 엔진·콘솔, 단일 웰 뷰어, 오류 전파와 엔진 단절을 포함한다.

PIN 발급·변경·복구, 파괴적 동작의 관리자 전용 여부, 패널 크기 프리셋, JPEG 품질·EXIF는 원명세의 미결정 사항이므로 이 버전에서 제공하지 않는다.
