## 1. 목적과 범위

본 시스템은 스캐너 4대와 플레이트 96슬롯을 관리하는 1200×800 LCD UI, 장비 제어 서버, 별도 가상장비 엔진·콘솔로 구성된다. LCD는 등록, 일정, 촬영 명령, 전송 상태, 최근 영상 버퍼와 장비 상태를 담당한다. 콜로니 판독·계수·리포트는 PC 소프트웨어 범위다.

포함 범위는 분석자/관리자 권한 전환, 등록·연속 등록·반출, 공통 촬영 루틴, 촬영 큐·단계, 이력 필터·CSV, 모듈 상태·캘리브레이션, 설정 하위 패널, 이벤트 로그·백업, 외부 가상장비 I/O, 단일 웰 영상 보기다.

## 2. v1.2 변경 사항

- 가상장비 상태 머신과 tick을 LCD 서버에서 `simulator-app/engine.mjs` 독립 프로세스로 이전했다.
- 시스템 실행 시 LCD와 Virtual Device Console을 서로 다른 Chromium 앱 창으로 연다.
- 헤더 사용자 칩, 분석자/관리자 전환, PIN 오류 잠금, 무조작 자동 복귀를 구현했다.
- 설정을 검사 루틴, 온도·CO₂, 유선 통신, 로그·백업, 장비 정보, 권한 설정으로 구성했다.
- 오늘 촬영·다음 일정, 상세 루틴·경과·총 회차, 연속 등록, 진행 프리뷰·큐, 이력 필터·CSV, 모듈 상태·캘리브레이션을 추가했다.
- 촬영 영상은 6-well 전체를 표시하지 않고 원형 마스크 안에 WELL 1/6 한 개만 표시한다.

## 3. 프로세스와 포트

```text
LCD Chromium 창 :8787
  ↕ HTTP/SSE
LCD/API 서버 server/index.mjs :8787
  ↕ HTTP polling/command
외부 가상장비 엔진 simulator-app/engine.mjs :8790
  ↕ HTTP
Virtual Device Console 창·정적 서버 :8792
```

외부 엔진은 스캐너 상태, 센서 입력, 액추에이터 출력, 작업 상태 머신과 100ms tick을 소유한다. LCD의 `RemoteDeviceAdapter`는 엔진 상태를 읽고 명령을 전달한다. 엔진이 종료되면 LCD는 `ENGINE_OFFLINE`, 링크 0/4로 전환한다. 콘솔을 닫아도 엔진은 유지되며, 엔진 프로세스를 종료해야 장비 연결이 끊어진다.

| 파일 | 역할 |
|---|---|
| `src/App.jsx` | LCD 화면, 역할 전환, 설정, 업무 흐름 |
| `server/index.mjs` | LCD 정적 파일, 도메인 API, SSE |
| `server/controller.mjs` | 플레이트·루틴·이력·세션·보존 정책 |
| `server/remote-device.mjs` | 외부 엔진 통신과 연결 복구 |
| `server/virtual-device.mjs` | 가상장비 상태 머신 클래스 |
| `simulator-app/engine.mjs` | 독립 가상장비 런타임과 I/O API |
| `simulator-app/app.js` | 별도 Virtual Device Console |
| `open-demo.sh` | 세 서버 시작과 두 창 실행 |

## 4. 화면 명세

### 4.1 전역 헤더와 내비게이션

헤더는 현재 화면 제목·부제, 평균 온도·CO₂, 링크 수·오류 수, 시각, 사용자 칩을 표시한다. 하단 탭은 현황, 등록, 진행, 이력, 장비, 사용자 설정이다. 상세 화면은 현황 탭에 속한다.

사용자 칩은 권한 전환 진입점이다. 분석자는 남색, 관리자는 황색 배경·주황 테두리로 상시 구분한다.

### 4.2 현황

- 스캐너별 수납 수, 오늘 촬영 매수, 상태, 8×3 트레이, 작업 진행률
- 미전송 2건 이상 경고
- 장비 오류·도어·엔진 단절 경고
- 상세·등록 이동

### 4.3 상세

- 물리 좌표 선택과 스캐너 전환
- 플레이트 ID, 투입 시각, 공통 루틴, 경과일, 현재/총 회차, 다음 촬영, 미전송
- 지금 촬영, 일정 정지·재개, 재전송, 반출
- 회차 메타데이터와 영상 보유·전송 상태
- 보유 영상은 WELL 1/6 한 개만 확대 표시

### 4.4 등록

- 사용 가능한 스캐너와 빈 슬롯 선택
- 투입 시각 직접 입력 및 지금 버튼
- 첫 촬영·총 회차 자동 계산, 설정 이동
- 등록 완료 후 완료 또는 다음 빈 슬롯 계속 등록

### 4.5 진행

- 이송, 물기 제거, 촬영, 수납 복귀, 전송, PC 저장 6단계
- WELL 1/6 라이브 프리뷰 자리, 조명과 Z축 상태
- 진행률, 일시정지·재개·비상정지
- 기한 도래 플레이트 촬영 큐와 회차

### 4.6 이력

- 플레이트·S번호·물리 좌표 검색
- 전체/7일/30일, 스캐너, 전송 상태 필터
- 위치, 회차, 투입, 다음 촬영, 보유 영상 수, 전송 상태
- 12행 페이지 이동, CSV 내보내기

### 4.7 장비

- 링크 속도, 카메라, 구동 4축, 히팅, 조명, 전원 상태
- 활성 오류 코드와 복구 안내
- 원점 복귀, 모듈 초기화, 확인 후 오류 해제
- 카메라 초점·배율, 4축 원점, 히팅 온도, 조명 광량 캘리브레이션
- 확인 후 전체 스캐너 재초기화, 이벤트 로그

### 4.8 설정

| 패널 | 권한 | 기능 |
|---|---|---|
| 검사 루틴 | 분석자·관리자 | 주기·기간·지연, 총 회차, 일정 재산정 확인, 자동 촬영 |
| 온도·CO₂ | 분석자·관리자 | 외부 엔진 4대 목표값 적용 |
| 유선 통신 | 분석자·관리자 | 스캐너별 연결·속도 표시 |
| 로그·백업 | 분석자·관리자 | 로그 JSON, 상태 JSON 내보내기 |
| 장비 정보 | 분석자·관리자 | 앱·엔진·슬롯·시리얼과 운영자 표시명 |
| 권한 설정 | 관리자만 | 세션 정책·잔여 시간, 분석자 전환 |

## 5. 권한 모델

장비 단위 단일 세션이며 기본 역할은 분석자다. 별도 로그인 화면은 없다.

- 분석자에서 사용자 칩을 누르면 4자리 PIN 다이얼로그가 열린다.
- PIN 오답은 횟수를 표시한다. 5회 실패하면 60초 잠긴다.
- 관리자 전환 시 무조작 타이머가 시작된다. 포인터·키보드 조작은 10초 단위로 세션 활동을 갱신한다.
- 4분 30초부터 잔여 30초 경고를 표시한다. 5분이면 분석자로 자동 복귀한다.
- 분석자 복귀 시 권한 설정 메뉴가 사라지고 열려 있었다면 검사 루틴으로 이동한다.
- PIN은 로그와 명령 영수증에 기록하지 않는다.

데모 PIN 기본값은 `0000`이며 `ADMIN_PIN` 환경변수로 실행 시 주입할 수 있다. PIN 초기 발급·변경·분실 복구 UI는 원명세 O-03 미결정 사항이므로 구현 범위에서 제외했다.

## 6. 가상장비 I/O

### 입력

- 장비 통신 연결, PC 전송 링크, 도어 센서, 카메라 실패
- Z_LIMIT, HEATER 오류 주입과 오류 해제
- 목표 온도 4~55℃, 목표 CO₂ 0~20%

### 출력

- 작업 상태·단계·진행률, Z축 mm, 조명, 히터, 현재 온도·CO₂
- TX, RX, ACK, 상태 머신 이벤트 최대 150건

### 엔진 API

| 메서드 | 경로 | 기능 |
|---|---|---|
| GET | `:8790/api/health` | 엔진 상태 |
| GET | `:8790/api/state` | 장비와 I/O 스냅샷 |
| POST | `:8790/api/device/command` | capture/pause/resume/stop/home/calibrate/reset/clearError |
| POST | `:8790/api/device/input` | 가상 입력·오류 |
| POST | `:8790/api/environment` | 환경 목표값 |

## 7. LCD API와 데이터

| 메서드 | 경로 | 기능 |
|---|---|---|
| GET | `/api/health` | LCD·엔진 연결 상태 |
| GET | `/api/state` | 화면 전체 상태와 세션 |
| GET | `/api/events` | SSE 실시간 상태 |
| POST | `/api/commands` | 도메인·장비·권한 명령 |
| GET | `/api/images/{name}.png` | 로컬 영상 호환 경로 |

명령은 8~100자 requestId를 사용한다. 같은 ID·같은 내용은 기존 ACK를 재사용하고 다른 내용은 거부한다. PIN은 지문·I/O에서 제거한다. 데이터는 `data/state.json`에 원자적으로 저장하며 회차 메타데이터는 반출 후에도 유지한다.

## 8. 영상 정책

- 각 플레이트의 성공 영상 참조는 최근 5회차만 `held`로 유지한다.
- 6번째 성공 시 가장 오래된 참조를 `expired`로 전환한다.
- 반출 시 보유 참조를 제거하고 촬영 시각·전송·상태 메타데이터는 유지한다.
- 미전송 2건 이상은 경고한다.
- 데모는 Wikimedia Commons의 `Ecoli_colonies.png` CC0 이미지를 동일하게 사용한다.
- UI는 이미지를 원형 프레임 안에 잘라 WELL 1/6 하나만 노출한다. 6-well 전체 배열은 표시하지 않는다.
- 외부 이미지이므로 인터넷 단절 시 사진 로딩은 실패할 수 있으나 회차·상태 기록은 유지된다.

## 9. 오류와 확인

도어 열림, 엔진 단절, Z축·히터·카메라 오류는 촬영을 차단하거나 진행 작업을 실패 처리한다. 반출·비상정지·전체 재초기화·오류 해제·루틴 저장은 확인 과정을 거친다. 오류 응답은 코드와 한국어 메시지를 제공하며, LCD는 토스트와 활성 오류 패널로 표시한다.

## 10. 미결정 사항 제외

원명세의 O-01 파괴적 명령 관리자 전용 여부, O-02 패널 크기 프리셋, O-03 PIN 발급·변경·복구, O-04 미전송 임계값 조정, O-05 JPEG 품질·EXIF는 결정되지 않았으므로 v1.2에서 임의 확정하지 않았다.

## 11. 검증

`npm run check`는 서버 단위 검사, Vite 빌드, Chromium 통합 검사를 실행한다. 검증 범위는 PIN 5회 잠금, 관리자 전환·자동 복귀, 등록·중복·보존 5장·재전송·반출, 외부 엔진과 콘솔, 촬영 완료, WELL 1/6 뷰어, 콘솔 오류의 LCD 전파, 엔진 종료 시 링크 0/4 전환이다.
